macOS 作为稳定基线，本会话只动 Windows 路径。

5. **快捷键平台化**：新建 `frontend/src/lib/platform.ts`，用 `window._wails.environment.OS`（回退 userAgent）检测平台；`KeyRecorder.vue` 与 `useShortcutsConfig.ts` 的修饰键/占位符按平台切换（macOS Cmd/Option，Windows Ctrl/Alt）。metaKey 在 Windows 归并到 Ctrl（避免 Win+ 被系统占用、且 "win" 非合法 token，合法的是 "super"）。

## 追加：关闭确认弹窗改用 Vue 前端组件（用户要求"弹窗可以用 vue 啊"）
- **原方案**用 Wails `app.Dialog.Question()` → Windows MessageBox，无法加"记住我的选择"复选框，按钮文字也不能本地化（必须硬写 "Yes"/"No"）。改为前端 Vue 弹窗后这些限制全部消失。
- **Go 端**：新建跨平台 `prefs_close.go`（状态机 + 动作执行）；`prefs_close_windows.go` 改为 `app.Event.Emit("blink:close-request")` 发事件给前端（不再弹原生对话框）；`breakservice.go` 新增 `ResolveClose(action, remember)` 和 `AckClose()` 绑定方法。
- **关键设计：两步握手防误判**。Go 端 `beginCloseAsk()` 挂 4s 兜底定时器（防前端无响应导致关闭按钮永久失灵）；前端收到事件立刻调 `AckClose()` 停表（只停定时器、不结束询问）；用户做决定后调 `ResolveClose()`。这样超时只衡量前端响应能力，不把用户思考时间算进去——否则用户盯着弹窗 4 秒后窗口会自己消失。
- **快照同步**：`useEngineState` 新增 `applyExternal(patch)`，在弹窗"记住选择"写 `closeAction` 时同时更新 `savedSnapshot`，否则用户之后改别的设置一保存就会把后端刚存的值覆盖回旧值。
- **前端组件**：`CloseConfirmDialog.vue`（玻璃拟态模态框，含说明、勾选框、保留后台/完全退出/取消三操作，ESC 与点遮罩取消）。
- **bindings 生成**：`wails3 generate bindings -f '' -clean=true -ts -i`（`$Call.ByID(hash)` 的 hash 不能手写，必须靠生成器）。注意 `-clean` 删目录重建有竞态，生成后需二次确认函数已写入。退出码始终为 1 但输出正常（wails3 CLI 已知行为）。

## 追加：启动时始终打开设置窗口（用户要求"不要默认进入后台"）
- **根因**：`%AppData%\Blink\settings.json`（Windows 路径 = `os.UserConfigDir()/Blink/settings.json`，即 `C:\Users\<user>\AppData\Roaming\Blink\settings.json`）有开发期残留的 `"onboarded":true,"autoStart":true`。旧 `ServiceStartup` 只在 `!Onboarded` 时调 `showPreferences()`，`Onboarded&&AutoStart` 时仅 `engine.Start()` 直接进托盘。
- **改动**（`breakservice.go` `ServiceStartup`）：无条件调 `showPreferences()`，再按 `Onboarded&&AutoStart` 决定是否同时启动引擎。三种场景：首次(Onboarded=false)→显示设置不启动；已引导+自动→显示设置+启动；已引导+非自动→显示设置不启动。窗口显示仍走 `Hidden:true`+前端 `watch(ready)→BreakService.ShowWindow()` 机制（与原 Onboarded=false 路径相同，已验证可用）。
- 注意：此改动影响所有平台（macOS 回归用户也会在启动时看到设置窗口）。若后续要"开机自启静默驻留"，需另加 start-minimized 选项。`go build`+`go vet`（GOOS=windows）均通过。

## 追加：修复 release-windows.yml 中 makensis 不在 PATH 的报错
- **现象**：CI 报 `"makensis": executable file not found in $PATH`（exit 127）。go-task 在 Git Bash 环境下用 `sh -c` 执行 `makensis`，而 NSIS 虽预装在 windows-latest（`C:\Program Files (x86)\NSIS`）但不在 bash 的 PATH 里。
- **修复**：在 build 步骤前加一步 `Ensure NSIS (makensis) in PATH`——遍历 `/c/Program Files (x86)/NSIS` 和 `/c/Program Files/NSIS` 找 `makensis.exe`，找不到则 `choco install nsis`，然后用 `sed 's|^/\([a-zA-Z]\)/|\U\1:/|'` 把 `/c/...` 转成 `C:/...` 写入 `$GITHUB_PATH`（正斜杠 Windows 也接受，避免反斜杠在 bash 里的转义地狱）。后续步骤的 PATH 即包含 NSIS 目录。
- 教训：windows-latest 上用 `shell: bash` 时，预装工具不一定在 bash PATH 里；go-task 用 `sh -c` 执行命令，继承的是 bash 的 PATH 而非系统 PATH。

## 追加：单实例——再次双击不启动新进程，拉已有实例到前台
- **问题**：再次双击编译后的二进制会启动新进程，而非激活已有实例。
- **方案**：Wails v3 内置 `SingleInstanceOptions`（`application.Options.SingleInstance` 字段）。Windows 用 named mutex (`wails-app-<uniqueID>-sim`) + 隐藏 message-only 窗口 + WM_COPYDATA 通信；macOS/Linux 用 flock + 信号。第二个实例在 `application.New()` 阶段就 `os.Exit(0)`，不创建任何窗口/托盘，无闪烁。
- **改动 1**（`main.go`）：`application.Options` 加 `SingleInstance: &application.SingleInstanceOptions{UniqueID:"com.blink.app", OnSecondInstanceLaunch: func(_){ showPreferences() }}`。回调在独立 goroutine 上触发（Wails 内部 `go func(){ for range secondInstanceBuffer {...} }()`），`showPreferences` 对 goroutine 调用者安全。
- **改动 2**（`prefs.go` `showPreferences` 已有窗口路径）：`w.Focus()` 后加 `platform.ForceForeground(uintptr(w.NativeWindow()))`。原因：Wails 的 `focus()` 在 Windows 只调裸 `SetForegroundWindow`，后台进程因前台锁静默失败（窗口可见但藏在别的窗口后面）。`ForceForeground` 用 `AttachThreadInput` 绕过该限制。包了 `runtime.LockOSThread()/UnlockOSThread()` 保证 Attach/Detach 在同一 OS 线程（goroutine 可能被调度到别的线程导致 detach 失效）。`ForceForeground` 在 macOS/其它平台是空操作。`w.NativeWindow()` 返回 `unsafe.Pointer`（Windows 上即 HWND），转 `uintptr` 不需显式 import `unsafe`（类型推断）。
- `go build`+`go vet`（GOOS=windows）通过。macOS 构建无法在 Windows 上验证（CGo），但 `ForceForeground`/`LockOSThread`/`NativeWindow` 均跨平台定义，应可编译。

## 追加：重构休息前提醒弹窗（PreBreakNotice.vue）+ 修复"2秒一跳"
- **需求**：弹窗 UI 与设置页割裂，要重构对齐；倒计时要按秒（目前 2 秒一跳）。
- **"2秒一跳"根因**：后端其实每秒 emit 一次（`tickInterval=1s`，`advancePhase` 在 PhasePreBreak 每 tick 都 emit）。但 `remainingSec = int(remaining/time.Second)` 向下取整 + Wails 主线程忙碌时 ticker 偶发延迟/丢 tick → 整数跳过（10→8→6）。前端原 `PreBreakNotice.vue` 直接显示 `ev.data.remainingSec`，于是观感成 2 秒一跳。
- **修复（纯前端，不动后端全局语义）**：本地用对齐到秒边界的 `setTimeout` 驱动倒计时（`Math.ceil((endAt-Date.now())/1000)`），`endAt` 由后端 `remainingSec` 锚定；后端 tick 仅在漂移 >=2 秒时才重新锚定（`seeded` 标志防末尾 0→1→0 闪烁）。`progress` = 1 - remaining/total，进度条 1s linear 平滑填充。
- **UI 对齐设置页**：弹窗改用 `.glass-strong` 面板（顶部高光 + 发丝边框，与设置页面板同款）、`rounded-2xl=16px`、4px `phase-prebreak` 强调条（同源 settings 的 phaseColor 点缀）、34px/300 细体数字（同源 hero 时钟排版）、`GButton(variant=ghost,size=sm)` 做"推迟"按钮、2px `phase-prebreak` 进度条（同源 hero__progress）。窗口仍是 380×108 透明浮层（未改 Go/window_options.go）。
- `vue-tsc --noEmit` 通过（EXIT=0）。

## 追加：Windows 托盘交互——右键菜单 / 双击开设置 / 删左键菜单
- **需求**：Windows 托盘左键单击不再弹菜单；右键弹菜单；双击左键开设置页。
- **背景**：Wails v3 在 Windows 不为托盘安装任何自动点击处理；WM_LBUTTONUP→OnClick、WM_RBUTTONUP→OnRightClick、WM_LBUTTONDBLCLK→OnDoubleClick，菜单不会自动弹出，必须由 handler 显式 `OpenMenu()`。原 `tray_platform_windows.go` 把 `t.OnClick(func(){ t.OpenMenu() })`（左键弹菜单），double-click 已接 `showPreferences()`。
- **改动**（`tray_platform_windows.go` `applyTrayPlatform`）：`t.OnClick` 改 `t.OnRightClick(func(){ t.OpenMenu() })`；删掉左键 `OnClick`。双击 `t.OnDoubleClick(func(){ go showPreferences() })` 保留。左键单击现在无任何动作。
- `go build`（GOOS=windows）通过。`showPreferences()` 调 `ForceForeground`（见上条），从托盘双击拉起设置页可正确置顶。
